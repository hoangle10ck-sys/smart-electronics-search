# Product information completeness

Public search results, suggestions, product detail responses, similar-product results, and AI Advisor cards must pass one shared readiness check before they are returned.

A recommendation-ready product needs:

- Product name, brand, model, and category.
- A non-empty description with description source evidence and at least one usable specification. Descriptions generated by the catalog import/enrichment scripts are summaries of stored specifications; they do not add inferred claims.
- A product image with verified status, documented reuse permission, source, license, and attribution. A missing image or a rights-pending image is not eligible.
- HTTPS product and specification source URLs.
- The existing verified product, URL, and publication statuses.

Incomplete records can remain in MongoDB for review, but they are excluded from public results and AI recommendations until the missing facts are sourced and verified. This can reduce the visible catalog while records are being completed.

## Finding missing fields

The authenticated Admin Console catalog coverage view reports missing descriptions, images or image rights, specifications, and URLs by category and model. The underlying read-only endpoint is `GET /api/admin/catalog/coverage`.

For curated seed products, the import now creates a short description directly from the already stored `specifications` field and records that provenance. The existing enrichment script can preview missing descriptions with:

```powershell
cd backend
npm run enrich:missing-content -- --descriptions-only --dry-run
```

The command connects to the database configured for that backend process. Run it only after confirming the process is pointed at a local or isolated test database. A dry run does not save changes. Do not use it against a shared or production database without a separate deployment and backup plan.

## Adding newly researched facts

Use an exact manufacturer/model match. Record the public HTTPS product page and specification source, each specification as stated by that source, and image source/license/attribution evidence. The Admin Catalog validator will not publish a product marked verified without a description, non-empty specifications, verified URLs, and verified image rights. Search snippets or a visually similar image alone do not verify a product.

Feed imports remain pending until missing image and product facts are verified. A feed price record does not by itself qualify the product for recommendation.

## Verification

From `backend/`:

```powershell
npm test
npm run build
```

These checks validate code and fixtures. They do not modify MongoDB or verify the current contents of a connected database.
